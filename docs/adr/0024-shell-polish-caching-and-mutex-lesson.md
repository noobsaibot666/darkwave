# ADR 0024: Shell polish, native menu offload, local playback cache

## Status

Accepted.

## Context

A second round of direct feedback on the running app covered layout/IA complaints (crowded spacing, misplaced controls, a broken-looking panel collapse), two real bugs (arrow-key selection not scrolling into view, and a re-emergence of the mutex-blocking problem from ADR 0023 — this time triggered by the Refresh button itself rather than an automatic scan), and several new feature asks (native menu offload for Undo/Redo/Shortcuts/License Report, a local playback cache, tasteful motion). This ADR covers that pass.

## Decision

**Panel collapse, done properly.** ADR 0023's collapse mechanism swapped `display: none` on the aside and changed `.shell`'s `grid-template-columns` between two fixed states with no transition — which is what "layout kinda getting broken" was describing: an instant snap with no interpolation. The rewrite keeps both `<aside>` elements permanently mounted and transitions `grid-template-columns` itself (`transition: grid-template-columns 320ms`), which WebKit interpolates smoothly between compatible track lists. Each panel collapses to a 52px strip rather than 0 — enough to keep its own toggle button visible as the "handle to bring the panel back" the request asked for, living inside a `.panel-head` that never gets hidden. The rest of the panel's content sits in a `.panel-body` that fades via opacity rather than unmounting, so nothing pops in or out abruptly. The transport bar's `left` offset transitions in step with the sidebar so the floating dock doesn't jump.

**Undo/Redo, License Report, and Shortcuts moved off the canvas.** All three are native menu items now (`Edit`, `Library`, `Help` respectively) rather than workspace buttons, per the explicit request that these aren't canvas-area concerns. Menu clicks emit Tauri events (`menu-undo`, `menu-redo`, `menu-export-license-report`, `menu-keyboard-shortcuts`) that the frontend listens for and routes to the same handlers the old buttons called — no logic duplicated, just relocated. License Report triggered with no project selected now sets a real status message telling the user to pick a project first, instead of silently doing nothing (it was previously gated by a disabled button; a menu item can't disable itself against arbitrary app state without more plumbing than this warranted).

**New Project is a modal, not an inline field.** The sidebar's always-visible text input became a single "+ New Project" button that opens a small dialog — same `create_project` command, no inline clutter for something used occasionally.

**Settings reorganized into real sections.** Library / Playback / Cache / Accessibility, each a card with a consistent icon–label–control grid (`.settings-grid` / `.settings-row`) instead of the previous flat stack. Browser density and preview cache limit are genuinely editable here (they already were as of ADR 0023; this pass is presentation, not new wiring).

**Two-tone waveform.** The transport waveform now renders as two stacked layers sharing the same peak data: a grey "unplayed" track and a colored "played" overlay clipped to `currentTime / duration` with `overflow: hidden`. Because both layers use identical fixed-width bars in the same order, the clip boundary always lands between bars correctly regardless of position — no separate progress-tracking logic needed beyond the existing `currentTime`/`duration` state. Clicking anywhere on it still seeks (ADR 0023); the fill now visibly starts from wherever the click landed rather than implying the whole track had played.

**Arrow-key navigation scrolls into view.** `ArrowUp`/`ArrowDown` already updated `selectedAssetId` (ADR 0023 fixed the row *highlight* not following); a new effect keyed on `selectedAssetId` calls `scrollIntoView({ block: "nearest" })` on the matching row (found via a `data-asset-id` attribute added to each row), so keyboard navigation never silently scrolls the selection out of frame.

**Local playback cache.** A `preview-cache` directory under app data holds copies of referenced (typically NAS-backed) assets, capped at the user's `preview_cache_limit_mb` (default lowered from 16GB to 2GB — the requested "enough to get started without blowing disk space"). `warm_library_cache` reads the asset list and media root once under the catalog lock, then releases it before doing any file copying — the same lesson as the mutex fix below, applied up front this time instead of after a bug report. `asset_playback_path` prefers a cached copy when one exists, falling back to the live NAS path otherwise. The cache is purged automatically on window close (`on_window_event` / `CloseRequested`) and can be cleared on demand from Settings; nothing about it persists across a full app restart by design, so a stale or partial cache can never accumulate into a real disk-space problem.

**The mutex lesson, applied a second time.** The Refresh button broke the app the same way the auto-scan in ADR 0023 originally did: `refresh_library` and `import_folder` both locked the catalog mutex once for the entire scan loop, so a folder with many new files (or, worse, the recursive walk discovering hundreds of files the non-recursive importer had never seen) blocked every other catalog-dependent command — tag lookups, playback, browsing — for the whole scan. Both commands now lock per file inside the loop instead of once outside it. This doesn't make the scan itself faster, but it means the rest of the app stays responsive while it runs, which is what "the app breaks" actually meant in practice: not a crash, a mutex holder that wouldn't let go.

**Motion.** Installed `motion` (the current name for Framer Motion, and the same library the original plan doc's design system section named "Motion for React"). Used for the four overlay surfaces that appear/disappear during normal use — Settings, New Project, Keyboard Shortcuts, and the search Filter dropdown — with a consistent fade+scale enter/exit rather than instant show/hide. Deliberately scoped to these transient surfaces rather than applied to persistent layout (the panel collapse, which is a layout concern, stays on CSS grid transitions where it belongs).

**AudioFlux (github.com/libAudioFlux/audioFlux) evaluated, not integrated.** It's a real, actively maintained C library for audio feature extraction (MFCC, spectral analysis, pitch, wavelet transforms) that squarely matches the plan's unbuilt "audio measurements/classification" stage. Not pulled in this pass because: it's C, requiring FFI bindings and a C toolchain in a build that's currently pure Rust/Node on both target platforms; it operates on decoded PCM, and this app has no general audio decoder (playback deliberately uses the OS's native `<audio>` element instead of a Rust decode pipeline — ADR 0004/0019); and it's a genuinely multi-day integration (bindings, cross-platform linking, a decode pipeline, feature-to-tag mapping, tests) that doesn't belong folded into a UI/UX and import-intelligence pass. Recorded here as the right next step when real audio analysis gets built, not as a rejection.

## Consequences

- Grid-template-columns transitions are a WebKit/Safari-supported but non-universal CSS feature; this app only ships on macOS and Windows via Tauri's WebView2 (Chromium-based) and WKWebView, both of which support it, so this isn't a portability risk here the way it might be for a general web target.
- The playback cache duplicates disk space for anything it warms (by design — that's the point), bounded by `preview_cache_limit_mb` and fully reclaimed on every app close.
- Settings' Browser density and Preview cache controls were already real as of ADR 0023; nothing about their *function* changed here, only their layout.
- AudioFlux integration remains a real, scoped-out future project, not a maybe.
